3:T750,<h1>Next.js App Router로 정적 블로그 만들기</h1>
<h2>왜 Next.js인가?</h2>
<p>정적 사이트 생성(SSG)에는 여러 선택지가 있습니다. Gatsby, Hugo, Jekyll 등등... 그 중에서 Next.js를 선택한 이유는:</p>
<ul>
<li><strong>React 생태계</strong> 활용 가능</li>
<li><strong>App Router</strong>의 간결한 구조</li>
<li><strong>TypeScript</strong> 기본 지원</li>
<li>활발한 커뮤니티</li>
</ul>
<h2>핵심 설정: Static Export</h2>
<pre><code class="language-typescript">// next.config.ts
const nextConfig: NextConfig = {
  output: "export",       // 정적 파일 생성
  trailingSlash: true,    // GitHub Pages 라우팅 호환
  images: {
    unoptimized: true,    // 이미지 최적화 비활성화 (정적 빌드용)
  },
};
</code></pre>
<h2>Markdown 파싱 구조</h2>
<p><code>gray-matter</code>로 frontmatter를 파싱하고, <code>remark</code>로 HTML로 변환합니다:</p>
<pre><code class="language-typescript">import matter from "gray-matter";
import { remark } from "remark";
import html from "remark-html";

const { data, content } = matter(fileContents);
const processedContent = await remark().use(html).process(content);
const contentHtml = processedContent.toString();
</code></pre>
<h2>파일 구조</h2>
<p>포스트는 <code>posts/YYYY/MM/slug.md</code> 형식으로 관리합니다:</p>
<pre><code>posts/
└── 2026/
    └── 03/
        ├── hello-world.md
        └── nextjs-static-blog.md
</code></pre>
<h2>GitHub Actions 자동 배포</h2>
<p><code>main</code> 브랜치에 push하면 자동으로 빌드 및 배포됩니다. 설정은 <code>.github/workflows/deploy.yml</code>을 참고하세요.</p>
